# 合同起草标准

仅在开展法律关系分析、设计合同结构或最终质检时读取本文件。

## 一、法律关系底稿

用下表先还原交易，再确定合同名称和条款：

| 维度 | 必须查明的问题 |
|---|---|
| 主体 | 谁签约、谁履行、谁决策、谁收付款；资质与授权是否匹配 |
| 目的 | 客户真正希望取得什么结果；合同标题与实际目的是否一致 |
| 标的 | 货物、服务、许可、数据、权益或组合标的分别是什么 |
| 控制 | 谁选择方案、实施行为、控制风险、保留原始证据 |
| 对价 | 现金、折扣、产品、资源或其他权益对应何项真实工作或成果 |
| 流程 | 下单、交付、验收、补正、开票、付款和结项的先后关系 |
| 资料 | 数据、病历、肖像、商业秘密、知识产权和品牌如何取得及使用 |
| 监管 | 是否存在准入、备案、伦理、广告、数据、反贿赂等叠加规则 |
| 退出 | 未履行成果、存量产品、已付款项、资料和持续义务如何处理 |

如一份协议同时包含采购、服务、许可或数据合作，应分别确定各部分标的、对价和责任，避免用“合作”二字掩盖复合法律关系。

## 二、重大澄清事项

优先将问题改写为可决策选项，例如：

- 结算：`A. 现金服务费 / B. 产品作价 / C. 采购折扣 / D. 其他`；说明各方案对税票、验收和监管定性的影响。
- 资料用途：`A. 内部反馈 / B. 对外品牌传播 / C. 学术发表 / D. 注册或研究`；不同用途分别设置授权和程序。
- 验收：`A. 形式完整 / B. 实质质量 / C. 分阶段验收 / D. 第三方检测`；明确付款是否挂钩。
- 成果权利：`A. 权利转让 / B. 独占许可 / C. 非独占许可 / D. 仅限项目使用`。

不要把事实问题伪装成法律问题。先查明实际安排，再作法律定性。

## 三、起草前提要确认

正式写合同前，将分析固化为Markdown并交律师确认。至少包括：

1. 我方代表主体和市场地位；
2. 已确认事实、作业假设和待确认事项；
3. 签约主体、实际履行主体及合同外参与方；
4. 法律关系定性、复合关系和可能的备选定性；
5. 资金、货物、服务、票据、数据及知识产权流向；
6. 主要法律依据、适用分析、核验来源和核验状态；
7. 拟用合同名称、章节结构及正常/异常履行闭环；
8. 核心风险分配、正文条款、批注和运营落实的分工；
9. 需要律师选择的方案及不同方案对合同结构的影响。

前提要的作用是让律师在投入完整起草前校验逻辑，不是另写一份长篇法律意见。用户确认后更新状态，并以确认后的版本作为合同起草依据。

## 四、表达视角

### 正文

- 面向合同相对方，使用确定、可履行、可验证的外部表达。
- 直接写义务和后果，不写内部分析过程。
- 用“应当/有权/不得/视为/构成”表达明确规则；必要时限定主观标准。
- 避免通过大量否定式声明替代真实交易描述。
- 不将患者、消费者、员工等第三方的法定权利写成客户“所有权”。

### 批注

- 面向客户内部决策和执行。
- 采用“依据—理由—建议”，短而具体。
- 对法律定性存在不确定性时，写明判断前提和保守处理方式。
- 对未确认的商业选项，给出选择及影响，不替客户预设。

## 五、履行闭环检查

对每项核心义务逐一检查：

1. 谁履行；
2. 履行什么；
3. 何时、何地、以何种标准履行；
4. 用什么文件或记录证明；
5. 谁在多长期限内验收；
6. 验收不合格如何一次性通知、补正、复验；
7. 是否影响付款、产品交付、所有权或风险转移；
8. 迟延、虚假、拒不补正或隐蔽问题触发何种责任；
9. 何时可以解除；
10. 解除后价款、货物、资料、保密及存续义务如何处理。

## 六、常见失败模式

- 先套合同类型，后解释交易，导致法律关系与业务不一致；
- 为追求“合规完整”在正文堆入大量客户自我限制；
- 只写付款比例，不写付款前提、验收证据和暂缓付款权；
- 将内部宣传、研究或数据使用提醒写成对外承诺，却未约束资料提供方；
- 把所有事项约定为双方对等，忽略风险实际控制者；
- 只列违约金，不定义一般/重大违约及损失范围；
- 解除条款没有处理未使用货物、存量资料、已付款和存续义务；
- 批注只有法条，没有该法条与本项目的连接及可执行建议；
- 只生成合同正文，不检查最终 Word 的结构和关键页面。
- 未经律师确认法律关系和合同结构即直接生成整份合同。
- 没有 Agent 自带 DOCX skill 时直接交付 Markdown，而未调用内置轻量 DOCX 脚本。

## 七、终检清单

- [ ] 事实、假设和待确认事项已区分
- [ ] 起草前提要已保存、已确认并与合同正文一致
- [ ] 法律关系与合同标题、鉴于、项目性质一致
- [ ] 客户方和市场地位已确认
- [ ] 主要义务分配给最能控制风险的一方
- [ ] 交付、验收、付款、补救和解除形成闭环
- [ ] 强制性义务与客户内部提示已正确分置
- [ ] 资金、货物、票据、数据和权利流向均可追溯
- [ ] 违约责任与具体义务逐项对应
- [ ] 终止后处理完整
- [ ] 法律依据已核验，未照搬失效或失准模板结论
- [ ] 批注符合“依据—理由—建议”
- [ ] Word已完成与当前工具能力相匹配的结构检查；轻量脚本不具备的复杂能力已说明
