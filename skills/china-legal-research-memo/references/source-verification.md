# 来源与核验规则

## 一、来源层级

按下列顺序寻找并核验来源：

1. 项目原始材料：合同、承诺、许可证、批复、会议文件、聊天和手写记录；
2. 现行法律、行政法规、司法解释、部门规章和地方性法规；
3. 制定机关、法院、检察院、监管机关、交易所等发布的原文；
4. 可核验全文的裁判文书、指导性案例、典型案例、行政处罚和监管问询；
5. 权威法律数据库中的法规沿革、案例信息和链接；
6. 专业论文、法律实务文章和媒体材料——仅限成熟中国律师事务所、律师协会（全国及省级）和以 `gov.cn` 结尾的政府网站。

第六层主要用于发现问题、关键词和定位原始来源，不宜单独支撑决定性法律结论。

### 上市公司信息披露（专门层级）

涉及上市公司事项时，信息披露材料单独走下列来源，法宝无对应模块，不以一般法规/案例通道代替：

- 公告原文：巨潮资讯网（cninfo.com.cn，证监会指定信息披露平台），上交所、深交所、北交所官网；
- 公告与监管检索：元典 securities 模块的公告检索（`rh_ssgsgg_search`）与证券监管处罚检索（`rh_zqcfws_search`）；
- 监管原文：证监会官网（csrc.gov.cn）的监管文件、问询函、行政处罚决定。

披露材料除满足"五、现行性核验"外，至少记录：公司全称＋证券代码、公告标题、公告类型、发布或披露日期、交易所或披露平台、可点击链接（巨潮／交易所／元典）、核验日期、支持或限制哪项结论。

### 禁引清单（硬约束）

AI 生成内容、个人博客、非律所自媒体、论坛问答，永远不作为论证依据；未经一手核验的法条、案号、金额、日期、比例和监管口径不得写入。上述内容只能作为检索线索，回一手来源核验属实后方可引用。

## 二、项目材料的引证

重要事实应指向具体材料和位置，例如：文件名、页码、条款、表格行、聊天日期或手写页码。对于扫描件和图片，记录原图位置；OCR 文本只能辅助检索，不能代替图像核对。

事实证据状态分为：

- `confirmed`：已有可靠材料并完成核对；
- `stated`：材料中有人陈述，但未独立确认；
- `assumed`：为研究暂作假设；
- `missing`：决定性事实缺失；
- `conflicted`：不同材料相互矛盾。

## 三、法规核验字段

每项决定性规范至少记录：

- 规范全称；
- 制定或发布机关；
- 效力层级；
- 文号；
- 公布日期、施行日期；
- 当前效力和沿革；
- 具体条款；
- 法宝或元典链接；
- 官方公开链接（存在时）；
- 核验日期；
- 支持或限制哪一项结论。

必须同时查看定义、适用范围、例外、程序、责任和配套规范。不得只截取对本方有利的一句。

## 四、案例核验字段

每个被正文依赖的案例至少记录：

- 案名、案号、法院、审级、裁判日期、案由；
- 文书类型和是否取得全文；
- 决定性事实；
- 适用法律；
- 引用段落或页码；
- 裁判理由和裁判结果；
- 后续审理或被改变情况；
- 与本事项相同和不同之处；
- 法宝或元典链接；
- 官方链接（存在时）；
- 该案例支持或限制的命题。

不要把当事人主张、法院转述或摘要编辑意见写成法院观点。

## 五、现行性核验

基准日期以实际研究日期或用户指定日期为准。至少检查：

- 是否现行有效、尚未生效、已被修改、部分失效或已废止；
- 引用条款在基准日期的具体文本；
- 是否有新法、修订草案、过渡期或配套规定；
- 地方规定是否适用于目标地域；
- 旧案例所依据的规范是否已变化；
- 主管机关名称、职权和办理程序是否调整。

旧规范可以用于说明历史沿革，但必须明确其历史状态，不得与现行规则混写。

## 六、主张—来源对应

正文中的重要主张应落入以下类型之一：

| 类型 | 说明 | 需要的支持 |
|---|---|---|
| `fact` | 本事项事实 | 项目材料和定位 |
| `rule` | 法律规则或程序 | 现行规范原文和条款 |
| `case_holding` | 裁判观点 | 裁判全文和具体理由 |
| `regulatory_practice` | 监管或办理实践 | 处罚、问询、官方答复或明确标注的访谈记录 |
| `secondary_view` | 学术或实务观点 | 作者、标题、日期和原文 |
| `inference` | 本团队推断 | 写明所依据的已核验前提和推理步骤 |
| `recommendation` | 业务或合规建议 | 说明依赖的规则、事实和风险偏好 |

推断可以存在，但不得伪装成来源原文。建议也不等同于法定义务。

## 七、冲突处理

不同来源冲突时：

1. 列出冲突的具体命题；
2. 比较规范层级、发布时间、适用范围和事实基础；
3. 核对是否存在新旧版本、一般与特别规定、不同地域或不同程序；
4. 无法消解的，保留两种口径并说明各自后果；
5. 指出哪项补充材料、主管部门确认或律师判断能够解决冲突。

不得为了得到完整答案而静默选择其中一个来源。

## 八、检索失败的表达

推荐写法：

> 在已检索的数据库及公开来源中，暂未发现与本事项事实结构完全一致的裁判或监管实例。现有结论主要依据上位规则及若干相邻案例，主管部门对具体办理方式的接受程度仍需进一步确认。

同时保留检索范围、关键词、地域、时间和日期。检索失败不是“规则不存在”的证明。

## 九、链接、留存与交付

- 交付物是单一文件：结论、分析和来源核验信息都在同一份文件中，以脚注形式嵌入，不另设内部台账。
- 来源脚注在正文按出现顺序编号并附可点击链接；律师审阅时据此查证，查证属实后由律师删减不需要的来源脚注再外发。
- 每个被正文依赖的案例都随交付物附案例原文文件包（含全文和元数据），不限于"长期复用"的案例。
- 用户要求保留法宝或元典链接时，链接必须可点击，不以纯文本替代；存在官方原文时，同时记录官方链接。
- 交付客户无需脱敏。
- 不在技能目录、公开仓库或通用缓存中保存客户材料。

## 十、脚注格式（8 类引注）

来源脚注按来源类型套用下列格式，编号按正文首次出现顺序递增，同一条来源多次引用用同一编号；有 URL 的一律用可点击 Markdown 链接。

| 来源类型 | 脚注格式 |
| --- | --- |
| 法律文件 | 《名称》第 X 条第 X 款，现行有效。来源：[链接](URL) |
| 司法案例 | 原告诉被告案由案，XX 法院（YYYY）XX 号民事判决书。来源：[链接](URL) |
| 网络文章/律所推文 | 律所/作者，《标题》，微信公众号/网站，YYYY-MM-DD。来源：[链接](URL) |
| 期刊文章 | 作者，《标题》，《期刊名》YYYY 年第 X 期。来源：[链接](URL) |
| 书籍 | 作者，《书名》，出版社 YYYY 年版，第 X 页。 |
| 学位论文 | 作者，《标题》，学校 YYYY 年硕/博士学位论文。 |
| 国家标准 | 发布机关，《标准名称》，GB/T 或 GB XXXX。 |
| 英文资料 | 作者，文题，卷期刊 页码 (年份)。 |

无 URL 的实体出版物（书籍、纸本期刊、学位论文）可省略超链接，但须保留完整出版信息。法条脚注须含名称、条号、原文可核验位置和时效性状态四项；案例脚注须含案号、审判机关和文书类型。
