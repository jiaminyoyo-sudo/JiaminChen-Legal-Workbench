## 1. 两种最小修订

### 法律内容最小

按以下顺序选择修改单位：

```text
不改 → 改字 → 改词 → 改短语 → 增删短句 → 改整句 → 改整段
```

只有前一级不能解决重要风险时，才进入后一级。

判断修改是否最小时，不比较“新文本是否更完整”，而比较“为了消除具体风险，最少需要改变什么”。

### Word 痕迹最小

即使法律上确需改整句，也要提取新旧文本的共同前缀、共同后缀，只标记真正变化的部分。不得因为操作方便把完整原句删除并重新插入。

新增例外、期限、责任主体或救济时，优先在准确锚点前后插入，不重做整个条款。

## 2. 不修改测试

出现以下任一情形，原则上不改正文：

- 只是律师表达习惯不同；
- 语句虽不完美，但不存在两种实质解释；
- 上下文已经明确同一事项；
- 法律已经产生明显且相同的先后履行或违约后果；
- 现有宽泛表述对客户更有利，改成具体期限反而增加客户违约风险；
- 所谓补充只是把原条款的应有之义重新写一遍；
- 风险发生概率、损失和交易重要性不足以支持增加谈判成本；
- 修改需要先确认商业安排，但事实尚未确认。

不要修改不可抗力等成熟通用条款，除非存在主体错误、适用范围明显失衡、通知或后果缺失等具体实质问题。

争议解决应看实际效果。工程所在地与甲方所在地实际相同且均有利于甲方时，不为形式统一改写。

## 3. 正文、批注与商业确认

### 直接修改

仅用于：

- 核心权利缺失；
- 对方义务、质量标准、验收或责任无法执行；
- 客户承担明显过重、无边界或不匹配的责任；
- 条款冲突、附件断裂或责任主体错误；
- 不修改会影响交易目的或重要救济。

### 仅作批注

用于：

- 谁承担手续、费用、审批或配合义务尚未确认；
- 原条款可以继续使用，但需要提示法律边界或操作风险；
- 修改方向取决于客户选择；
- 附件没有对应项目，不能直接在正文虚构引用；
- 需要提醒财务、业务或运营确认，但不值得增加合同文字。

### 客户口径

批注说明：

1. 当前条款会产生什么实质影响；
2. 为什么建议修改或确认；
3. 客户需要确认什么；
4. 不同选择如何影响责任。

批注是律师直接给公司经办人员阅读的文本。需要对方确认或执行时，写“请公司确认”“请公司核实”“请公司结合实际执行”，不得写“请客户确认”“建议客户”等内部工作称谓。涉及多个公司或合同主体时，改用具体主体名称或“甲方／乙方”，避免指代不清。

不要使用内部工作标签替代解释，不写“本处有风险，请确认”即结束。

### 法律边界型批注

条款表面对公司有利但存在不生效、部分无效、被调减或不能排除的法定边界时，不宜只写“有无效风险”，也不宜直接用大段法条替代分析。按照下列顺序组织：

1. **法律边界**：写明规范层级、核心规则及对应法律后果；
2. **核心理由**：说明为何修改、删除或保留，解决的是条款效力、举证、执行还是责任叠加问题；
3. **公司利益**：说明处理后仍保留的权利，以及降低的无效、调减、解除或举证风险；
4. **公司动作**：对个案事实和商业选择，明确请公司填写、确认、决定或留存的材料。

可复用句式：

```text
本处删除／调整……。根据……，……；原约定存在……风险。这样既保留公司……权利，也降低……风险。
```

```text
本处参考……的操作口径；该文件属于合规参考，并非强制法定标准。请公司结合……确认最终期限、比例或方案。
```

```text
原条款较法定标准更有利于相对方，本稿暂予保留；如公司希望调整至法定边界，请公司结合实际执行和谈判情况决定。
```

写作要求：

- 引用规则以足以支撑结论为限，一般不整段粘贴法条；
- 明确区分“应当／不得／无效／不生效”等强制或裁判边界与“通常／一般不宜／建议”等参考口径；
- 对修改和未修改都说明理由，尤其说明为何保留对公司有利但仍合法的原约定；
- 将抽象提示转化为具体动作，如填写人员和秘密范围、确认比例、列明清单、说明全国范围理由或留存履行证据；
- 通常控制在二至五句；重大效力或责任问题可以适当展开，但不得把批注写成完整法律意见书。

## 4. 程序义务的执行性

增加书面申请、盖章确认、授权书、测试记录、影像留痕、审批时限前，依次判断：

1. 交易是否足够复杂；
2. 该材料是否是未来举证的关键且没有更轻手段；
3. 当事人是否具备日常执行能力；
4. 不履行该程序是否会产生与风险不相称的违约；
5. 通知、微信确认、邮件确认等更轻方式能否解决。

简单安装、维修或低频服务通常优先使用：

```text
书面通知 → 对方代表确认
```

不要默认升级为：

```text
变更申请＋原因说明＋价款工期测算＋盖章授权＋双方盖章确认
```

工期顺延通常以乙方及时书面通知为基础即可；可增加“乙方未及时通知或者延误由乙方造成的，不得主张顺延”，无需与其他条款重复设置多层申请。

## 5. 全文与附件勾稽

增加附件引用前检查：

- 附件名称是否准确；
- 附件是否实际存在；
- 附件是否真的列明排除项、甲方承担项或技术标准；
- 正文新增义务是否需要同步修改报价单、清单或技术附件；
- 附件排除项与总价包干范围是否冲突。

价款排除已经在附件清楚列明时，不在正文重复增加概括性包干条款。确需补充时，在附件“价款排除”末尾作最小增加，不改变工程范围条款。

不得写“附件明确列明由甲方承担的除外”，而附件中没有任何甲方承担项目。

## 6. 履行、验收与责任分层

按以下结构安排：

```text
业务条款：标准和履行
验收条款：检查、异议、整改、重新报验
质保条款：质保范围、期限和具体措施
违约责任：违约金、赔偿、解除和损失
```

不要在验收程序中同时塞入付款效力、全部损失、开拆复验、证据清单和多项违约后果。

隐蔽工程已经约定“验收后进入下一道工序”时，不自动增加全套施工记录、影像、检测资料和擅自覆盖开拆责任。只有项目复杂度或争议风险确有必要时才增加。

未验收合格的核心补充通常是：

```text
乙方应限期整改并重新报验。
```

不要把甲方“及时验收”机械改成固定工作日，除非客户需要明确时限并愿意承担相应义务。

## 7. 常见条款校准

### 设备、材料和利旧

- 先确认设备由谁供应；
- 乙方仅提供安装服务时，不把设备本身的质量保证全部转嫁给乙方；
- 乙方同时供应新增设备时，将保证限定为“乙方提供的新增设备、材料”；
- 利旧部分原则上不纳入乙方质保；
- 保留“因乙方拆改、安装、调试等操作造成损坏的除外”；
- 不默认要求双方共同清点、测试并形成书面或影像记录。

### 场地、物业和作业手续

“甲方提供符合施工条件的场地，协调物业及相关单位”已经清楚时，不为表达习惯改成“协助乙方沟通”。

设备进场、高空作业、物业审批的办理主体和费用属于商业责任分配。合同、附件未明确时只批注，不直接改为乙方全部承担。

### 施工组织和变更

对简单工程，不要求复杂变更单和多层授权。需要控制新增费用或工期时，以书面通知和甲方代表书面确认为基本结构。

### 发票和付款

可以增加“乙方应在甲方各期付款前开具相应合法有效的发票”。

已经约定先开票、后付款时，不重复增加“乙方未开票或开票不合规，甲方有权顺延付款且不承担违约责任”，除非合同其他条款会造成冲突。

税率是否符合财务处理要求，可以批注提醒财务确认，不在合同审查中展开无必要论证。

### 质量、产品瑕疵和产品缺陷

区分：

- 产品或履行不符合约定：型号、性能、制冷、漏水、异响、振动等；
- 施工质量不合格：安装、调试、新增辅材不符合约定或适用标准；
- 产品缺陷：存在危及人身、其他财产安全的不合理危险。

先具体化适用范围和质量标准，再设计修理、重作、更换、退货、减价等补救；只有严重影响正常使用、安全或合同目的实现时，才触发解除、退款和较重违约金。

产品缺陷造成损害的责任与普通质量整改分开规定，不以普通违约金替代人身、财产损害责任。

### 质保

质保措施应与合同类型匹配。安装合同混合设备供应时，区分厂商质保和乙方施工质保，约定期限不一致时可采用较长者。

核心部件经两次维修仍不能正常使用的，可以要求换新；不要把所有质保项目都改成同等严格的换新义务。

### 资质、转包和分包

原文已有销售资格时，保留原逻辑，只最小增加“依法需要的施工或作业资质”。可以增加“不得转包、违法分包”，不要重写成复杂资质清单。

保证条款中原则上不混入大段赔偿机制；原文已有损失承担时，可作最小完善，详细责任仍放违约责任章。

### 保密

根据交易内容判断重要性。普通设备买卖、安装合同没有实质技术秘密时，不为提高完整性扩写保密条款。

### 违约责任

这是全文最高优先级之一。完成正文修改后重新对照：

- 关键义务是否有专项责任；
- 一般义务是否有通用兜底；
- 责任是否相对公平或适度有利于客户；
- 违约金计算基数、触发条件是否明确；
- 违约金不足是否补足损失；
- 是否需要列举检测鉴定、拆除恢复、第三方索赔、律师费等损失。

客户主要是权利方时，可以适度扩张可赔损失范围；客户可能主要承担责任时，谨慎扩大范围并考虑责任上限。

## 8. 修订计划和复核

每项计划至少记录：

```text
条款位置：
具体风险：
处理方式：不改／批注／局部红线／结构性修订
最小操作：
是否影响附件或其他条款：
批注理由：
```

复核时重点寻找：

- 整句、整段删除后重插；
- 与原文同义的新增内容；
- 未确认的费用或手续分配；
- 新增但无法执行的程序；
- 不存在的附件引用；
- 业务条款和违约责任重复或冲突；
- 核心修改没有客户口径批注；
- 批注使用“请客户”“建议客户”等内部称谓，而非“请公司”或具体合同主体；
- 法律边界型批注只摘法条或只报风险，没有解释修改／保留理由和公司后续动作；
- 把合规指引、行业惯例等参考口径写成强制法定标准；
- 形式变化但实质未变化的修订。

发现上述情形，先删除不必要修改，再拆分保留的操作，不以增加更多解释弥补过度修订。
