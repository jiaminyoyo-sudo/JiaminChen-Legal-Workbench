# 客户 Wiki 审计清单

## 运行确定性审计

在项目 Wiki 上运行：

```bash
python3 scripts/audit_wiki.py check <项目>/wiki
python3 scripts/audit_wiki.py report <项目>/wiki --format json
```

脚本检查结构，不判断法律内容。重点包括：

- `规则.md`、`索引.md`、`日志.md`、`原材料地图.md` 是否存在；
- Wiki 内部 `[[...]]` 链接是否断裂：`目录/页面` 按 Wiki 根目录解析，裸页名优先按当前目录解析，`./` 和 `../` 按当前页面解析；Markdown 相对链接按当前页面解析；
- 索引是否遗漏明显新增的 Markdown 页面；
- 日志和材料地图中的明确页面链接是否存在；
- 页面标题是否重复到足以造成路由歧义；
- 页面是否缺少来源、确认时间或当前/历史说明的明显线索；
- 是否出现绝对本机路径、Token 或课程包不应携带的敏感内容。客户 Wiki 的材料地图可能合法保留绝对原材料路径，这类结果默认是警告，不等于结构错误；课程脱敏发布前仍应人工复查。

## 人工内容审计

脚本报告后仍需人工核对：

- 当前口径是否和最新律师确认一致；
- 旧方案是否明确保留为历史而非当前规则；
- 个案妥协有没有被扩大成通用客户政策；
- 法律边界是否写清适用条件、例外和来源；
- 事项后续版本是否更新了原页而不是制造重复页面；
- 即时咨询是否登记了材料来源和最终口径位置；
- 通用律师方法是否误写入客户 Wiki。

审计发现内容疑点时，只提出复核清单，不用脚本批量补齐或重写法律页面。
